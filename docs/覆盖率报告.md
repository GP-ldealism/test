# 测试覆盖率报告

日期：2026-11-17（Asia/Shanghai）
对象：`pytest tests` 全量离线用例对 `app/` 的语句覆盖。
结论：**总覆盖率 83%**（1329 条语句，未覆盖 228 条）。缺口集中在两处——需要 GPU 的真实推理封装 `app/restore.py`（36%）与 Gradio 界面 `app/ui.py`（31%）；其余八个模块都在 92% 以上，未覆盖行几乎全是防御性报错分支。

## 1. 环境与方法

覆盖率工具装在仓库内的临时目录，**不污染共享 lanpaint 环境**，也不进版本库：

```powershell
$py = 'D:\Study\Postgraduate\GPT\envs\lanpaint\Scripts\python.exe'
& $py -m pip install --target .cache\cov-deps pytest-cov     # pytest-cov 7.1.0 / coverage 7.17.3
$env:PYTHONPATH = (Resolve-Path .cache\cov-deps).Path
& $py -m pytest tests -q -p pytest_cov --cov=app --cov-report=term-missing `
      --cov-report=json:.cache\coverage.json --basetemp .cache\pytest-cov
```

- 用例：133 passed（与 CI 一致，未联网、未加载扩散模型）。
- 产物：`.cache/coverage.json`（明细）与终端表格；`.cache/` 按 `.gitignore` 不入库。
- 只统计 `app/`（`scripts/`、`analysis/`、`ci/` 是入口或离线分析，不属被测单元）。

## 3. 缺口解释

### 3.1 真实推理与界面（36% / 31%）：由真实运行替代

`app/restore.py` 的 77 行未覆盖集中在 `_build_model`、`_PIPELINE_CACHE`、`restore()` 主循环与 NFE 计数包装——它们需要 2.2 GB 权重与 NVIDIA GPU，单元测试用假 runner 注入，属于**有意不测**。`app/ui.py` 的 83 行未覆盖是 Gradio 事件处理与 `run_repair` 主流程，同样依赖真实服务。

替代证据（都在仓库里可查）：

| 模块 | 替代验证 | 结果 |
|---|---|---|
| `restore.py` | `scripts/smoke_inference.py --runs 1`（2026-11-17 干净克隆） | NFE=120、31.67 s、2730 MB、无 NaN/全黑 |
| `restore.py` + `ui.py` | `scripts/check_ui.py` | `UI_REAL_GPU_PASS`，K=5、35.44 s、结果图与配置可下载 |
| `ui.py` 输入处理 | `tests/test_ui.py`（4 项） | 笔迹提取、背景保留、掩码对齐、空/全缺失掩码 |

### 3.2 其余模块（92%–98%）：几乎全是防御性报错

## 4. 结论

- **核心决策逻辑覆盖充分**：预算分档、规则冻结、指标计算、实验编排均 ≥92%，主流程没有被漏测的静默分支。
- **未覆盖部分不是"忘了测"，而是"不能在单测里测"**（GPU/界面）或"只在该报错时走到"。前者有真实运行证据，后者属可接受的残余风险。
- 需要警惕的不是覆盖率数字，而是 `app/experiment.py` 的两条失败分支（`warmup` 与 `evaluate` 失败）——它们只在与历史运行不同的环境下才会触发，一旦出错会影响 `comparison_complete` / `equal_nfe` 的判定。

## 6. 与 CI 的关系

CI（`.github/workflows/cpu.yml`）目前只跑 `ruff` + 离线 pytest，不生成覆盖率，以保持分钟级反馈。若需要在 PR 上看到覆盖率，可在 `ci/requirements.txt` 增加 `pytest-cov` 并给 pytest 加 `--cov`，代价是构建时间增加约 10 秒。
